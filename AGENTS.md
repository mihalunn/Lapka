# AGENTS.md — точка входа для агентов в Lapka

## Что это

Lapka — семейное веб-приложение для хранения истории питомцев и планирования
ухода. Это учебный pet-проект Михаила Долгова и полигон AI-инженерии.

Процесс разработки и его текущая миграция описаны в `MIGRATION.md`. Продуктовые
требования находятся в `docs/product/`.

## Где что лежит

- Продукт и границы: `docs/product/01-product-brief.md`,
  `docs/product/02-mvp-scope.md`.
- Сценарии и домен: `docs/product/03-analysis.md`.
- UX/UI-контракт и токены: `docs/product/04-design-spec.md`.
- Архитектура: `docs/product/05-architecture.md`.
- Задачи и DoD: `docs/product/06-backlog.md`.
- Процесс миграции: `MIGRATION.md`.

Следующие пути появятся на следующих фазах миграции:

- контекст: `docs/ai-context/`;
- решения: `docs/adr/`;
- активная задача: `docs/state/current-task.md`;
- память процесса: `docs/state/progress.md`;
- спецификации: `docs/specs/T-XXX.md`;
- промпты: `docs/prompts/`.

## Как брать задачу

1. Прочитать `MIGRATION.md` и определить текущую фазу.
2. Если существуют `docs/state/current-task.md` и spec задачи, прочитать их.
3. Читать только документы, на которые ссылается spec. Не сканировать весь
   репозиторий без необходимости.
4. До появления spec-файлов брать задачи только по прямому указанию владельца из
   `docs/product/06-backlog.md`.

## Пайплайн витка

Утверждённая spec → тесты RED → минимальная реализация GREEN →
`npm run check` → запись в `progress.md` → ревью владельца.

Пока соответствующая фаза миграции не создала spec или state-файлы, следовать
контрольным точкам `MIGRATION.md` и не имитировать отсутствующие артефакты.

## Жёсткие запреты

Без подтверждения владельца нельзя:

- устанавливать зависимости;
- менять `docs/product/*`;
- создавать ADR или менять принятое решение;
- удалять файлы и папки;
- работать с секретами и `.env`;
- расширять scope задачи;
- выполнять merge в `main`.

Также запрещено:

- реализовывать критерии приёмки до RED-тестов;
- выдумывать API-контракты, поля или поведение;
- оставлять закомментированный код и `console.log`;
- завершать виток без `npm run check`;
- самостоятельно объявлять результат принятым вместо владельца.

## Если ты не знаешь

Не додумывай. Остановись и спроси:

> В каком документе это описано? Если ни в каком — нужно ли создать или
> дополнить spec?

## Команды

```bash
npm run dev
npm run format
npm run lint
npm run stylelint
npm run typecheck
npm run test
npm run build
npm run check
```

Сообщения коммитов используют Conventional Commits, а описание после типа
пишется по-русски строчными буквами.
