# Архитектурные решения Lapka

ADR фиксирует принятое архитектурное решение и причину выбора. ADR не заменяет
продуктовые требования и не используется для описания временной задачи.

Новый ADR или изменение принятого решения требует подтверждения владельца.
Принятый ADR не переписывается задним числом: изменение оформляется новым ADR, а
старый получает статус `superseded by ADR-XXX`.

## Именование

```text
ADR-XXX-short-name.md
```

Номера выдаются последовательно и не переиспользуются.

## Шаблон

```markdown
# ADR-XXX: Название решения

Дата: YYYY-MM-DD. Статус: proposed | accepted | superseded by ADR-YYY

## Контекст

Почему возник вопрос и какие ограничения важны.

## Решение

Что выбрано и почему.

## Последствия

Что становится проще, какие ограничения и риски остаются.
```

- `ADR-003-css-modules-tokens.md` — CSS Modules и дизайн-токены.
- `ADR-004-forms-rhf-zod.md` — формы через React Hook Form и Zod.
