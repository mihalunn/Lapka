# ADR-002: HTTP-моки через MSW на этапе A

Дата: 2026-10-07. Статус: accepted. Подтверждено владельцем: 2026-10-07.

## Контекст

Frontend-сценарий разрабатывается до появления настоящего backend. Прямой импорт
fixtures в компоненты не проверяет HTTP-границу, состояния запроса и будущий
контракт API.

Нужен способ разрабатывать загрузку, ошибки и мутации так, чтобы переход к
backend не требовал переписывать компоненты.

## Решение

- На этапе A Mock Service Worker перехватывает реальные HTTP-запросы приложения.
- Fixtures используются только внутри mock handlers.
- Компоненты и API layer не импортируют fixtures напрямую.
- Моки поддерживают управляемые задержки и ошибки для проверки UI-состояний.
- Изменения хранятся в памяти вкладки и сбрасываются после перезагрузки.
- Форматы ответов соответствуют контрактам `{ data, meta }`, `{ data }` и
  `{ error }`.

## Последствия

- UI работает через ту же сетевую границу, что и с будущим backend.
- Loading, empty и error можно проверять до появления сервера.
- Перезагрузка сбрасывает demo-изменения; это ограничение явно описывается в
  приложении и README.
- MSW подключается в задаче T-006 после отдельной контрольной точки зависимостей.
- `localStorage` не используется как скрытая замена backend.
