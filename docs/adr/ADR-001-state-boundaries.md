# ADR-001: Границы состояния и RTK Query

Дата: 2026-10-07. Статус: accepted. Подтверждено владельцем: 2026-10-07.

## Контекст

Lapka работает с семейным пространством, питомцами, записями истории и
календарными событиями. Эти данные приходят через API, кэшируются и изменяются
мутациями. Одновременно интерфейсу нужны локальные меню, подтверждения, формы и
воспроизводимый выбор питомца.

Хранение всех видов состояния в Redux создаст дублирование, усложнит
синхронизацию и скроет владельца данных.

## Решение

- Серверные данные и результаты мутаций хранит RTK Query.
- Обычный Redux slice создаётся только для действительно глобального
  клиентского состояния.
- Значения и ошибки формы хранит React Hook Form.
- Небольшое визуальное состояние хранится локально в React-компоненте.
- Выбранный питомец и воспроизводимые фильтры кодируются в URL.
- API-данные не копируются из RTK Query в slices.

## Последствия

- У каждого вида состояния есть явный владелец.
- Кэш, загрузка, ошибки и инвалидация серверных данных сосредоточены в API layer.
- Ссылку на выбранного питомца можно открыть повторно.
- Перед добавлением slice нужно доказать, что состояние глобальное и не является
  серверным, формовым или локальным.
- Redux Toolkit и React Router подключаются только в задачах, где впервые
  необходимы.
