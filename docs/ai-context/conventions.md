# Конвенции разработки Lapka

Статус: утверждено владельцем 2026-10-07.  
Источники: текущий каркас, `docs/product/04-design-spec.md`,
`docs/product/05-architecture.md`, `AGENTS.md` и `MIGRATION.md`.

## Принцип минимальной структуры

- Код организуется по ответственности: `app`, `pages`, `widgets`, `features`,
  `entities`, `shared`, `mocks`.
- Слой или папка создаётся только вместе с первой реальной ответственностью.
- Не создавать пустую архитектуру «на будущее».
- Компонент сначала остаётся рядом с местом использования. Перенос в shared
  оправдан только повторным использованием с одинаковым контрактом.

## Имена и файлы

- React-компоненты, типы и интерфейсы: `PascalCase`.
- Переменные, функции и hooks: `camelCase`.
- Пользовательский hook начинается с `use`.
- Константы уровня модуля: `camelCase`; `UPPER_SNAKE_CASE` только для настоящих
  неизменяемых системных констант.
- Файл компонента: `ComponentName.tsx`.
- CSS Module: `ComponentName.module.css`.
- Тест рядом с кодом: `ComponentName.test.tsx` или `utility.test.ts`.
- Не использовать сокращения, если они делают предметный смысл неясным.

## Импорты

Пока alias не настроен, используются относительные импорты.

Группы разделяются пустой строкой:

1. внешние библиотеки;
2. внутренние модули;
3. стили и статические ресурсы.

Внутри группы импорты располагаются стабильно и без ручной перестановки ради
косметики. Текущая ESLint-конфигурация не проверяет порядок импортов
автоматически; добавление такого правила требует отдельного обоснования и
контрольной точки для зависимости, если она понадобится.

## TypeScript и React

- Не использовать `any` без документированной причины.
- Типы должны описывать реальный контракт данных, а не скрывать неизвестность.
- Не дублировать вычисляемые значения в state.
- URL владеет выбранным питомцем и воспроизводимыми фильтрами.
- RTK Query владеет серверными данными, React Hook Form — формами, локальный
  React state — небольшим UI-состоянием.
- Пользовательское поведение покрывается тестом до реализации: RED → GREEN.
- Тесты взаимодействуют с интерфейсом по ролям и доступным именам, а не по
  внутренним деталям компонентов.

## Стили

- Компонентные стили — CSS Modules.
- Глобальные стили содержат только reset, foundations, токены и правила уровня
  приложения.
- Цвета, отступы, радиусы и типографика берутся из CSS custom properties.
- Базовые шкалы и контрольные ширины определены в
  `docs/product/04-design-spec.md`.
- Не создавать отдельные несвязанные mobile-компоненты; один компонент
  перестраивается на контрольных диапазонах.
- Интерактивная область не меньше 44 × 44 px, focus заметен, reduced motion
  учитывается.
- Stylelint и Prettier должны проходить без отключения правил ради единичной
  ошибки. Исключение требует объяснения в spec или ADR.

## Коммиты

- Формат: Conventional Commits.
- Тип пишется латиницей строчными буквами: `feat`, `fix`, `docs`, `test`,
  `refactor`, `chore`.
- Описание после двоеточия пишется по-русски, строчными буквами и без точки.
- Один коммит содержит одно проверенное изменение.
- Коммит, merge и push выполняет только владелец.

Пример:

```text
docs: добавить контекст архитектуры
```

## Проверка

Перед передачей владельцу агент без напоминания запускает:

```bash
npm run check
```

Отдельное сообщение «готово» не заменяет зелёные проверки, diff и ревью.
